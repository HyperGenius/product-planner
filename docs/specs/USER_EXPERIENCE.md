# ユーザー体験（UX）定義

## 1. UXビジョン（コアコンセプト）
**「入力は最小限、計算は全自動。現場の思考を止めない”おまかせ”生産管理」**

本アプリの最大のミッションは、「生産管理タスクはこのアプリに任せて、従業員はものづくりに専念できる環境を作ること」である。
多忙な現場に新たな入力タスクや「システムのための作業（手動での工程パズルなど）」を強いることなく、システムが現場のスピード感に合わせて最適解を提示する体験を目指す。

## 2. ターゲットユーザーとペルソナ

### ペルソナA：注文管理担当（ベテラン従業員）
* **属性:** 現場の生産工程の流れは把握しているが、ITシステムの複雑な操作は好まない。
* **状況:** 日々、顧客からの電話やFAXでの注文対応と、現場での実作業に追われている。
* **課題:** 顧客からの「いつ納品できる？」という問い合わせに対し、勘や経験に頼らず、即座に正確な回答をしたい。

### ペルソナB：工場長兼社長
* **属性:** 従業員20名規模の工場のトップ。製品仕様から生産工程、顧客との関係値まで全てを把握している。
* **状況:** 現場の生産がスムーズに進んでいるか、納期遅れのリスクがないかを常に気にかけている。
* **課題:** 納期遅れが発生しそうな場合、いち早く察知して顧客への事前交渉や、現場への「特急」指示などのリカバリーを最小限の労力で行いたい。

## 3. JTBD（片付けるべき用事）と Aha! モーメント（価値を実感する瞬間）

### ① 納期回答の即時化（担当者向け）
* **JTBD:** 顧客から注文を受けた際、現在の工場の負荷状況を崩さずに「最短でいつ納品できるか」を、誰にも相談せず数秒で把握したい。
* **Aha! モーメント:** 注文の基本情報（製品・数量・希望納期）を入力して「シミュレーション」を押した瞬間、バックグラウンドで全自動計算が走り、**魔法のように「最短納入可能日」がズバリ提示された時。**

### ② 特急オーダーの自動割り込み（担当者・社長向け）
* **JTBD:** 顧客の希望納期にどうしても間に合わない（または緊急のねじ込み依頼が来た）際、他の作業を後回しにしてでもスケジュールを再構築したい。
* **Aha! モーメント:** 「特急（優先度：高）」を指定して再計算させた際、**システムが自動でパズルを組み直し、「この特急を入れると、代わりにこの3つの注文が〇日遅れます」という影響範囲（差分）だけをパッと提示してくれた時。**（人間はそれを見て「許容範囲か」をジャッジするだけで済む）

### ③ リスクの早期発見（社長向け）
* **JTBD:** 朝一番にシステムを開いた際、今日〜今週で遅延しそうなオーダーがないか一目で確認し、先手を打って対策したい。
* **Aha! モーメント:** ダッシュボードを開いた瞬間、順調なオーダーは省かれ、**「⚠️ 納期遅延リスクのあるオーダー」だけがトップにリストアップされており、自分が今どこに介入すべきかが一瞬で理解できた時。**

## 4. UI/UX 基本設計原則（デザインプリンシプル）

1. **手動エディタより、全自動シミュレーション**
   * オーダーごとの工程（ガントチャート）の手動ドラッグ＆ドロップ編集機能は、原則として現場には操作させない（UIから隠蔽、または非推奨とする）。
   * 全ては「マスター定義（Process Routing）」に基づく自動割り付けと、「優先度（特急フラグ）」によるシミュレーションのやり直しで解決する。
2. **システムが提案し、人間が承認する（Human-in-the-loop）**
   * スケジュール変更時、システムは「こうなります（影響範囲）」を提示し、ユーザーは「確定（承認）」ボタンを押すだけのアクションに留める。
3. **「例外（アラート）」ファーストの画面設計**
   * ダッシュボードや一覧画面では、正常に進行しているものよりも「遅延」「マスター未設定」などの例外状態を最も目立たせ、ユーザーの注意を誘導する。
4. **ホワイトボックスな自動化（納得感の醸成）**
   * 自動計算の結果には「なぜそうなったか（制約や押し出しの影響）」を視覚的に明示し、ユーザーの「システムへの信頼」を損なわない設計とする。
5. **例外入力によるキャリブレーション（Management by Exception）**
   * 計画と実績のズレを修正する際、細かな「完了報告」は求めない。「遅れたもの（予定通りいかなかったもの）」だけを修正し、再計算させることで、最小の入力負荷でシステムを現実に同期させる。
