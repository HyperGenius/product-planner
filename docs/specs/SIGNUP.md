# サインアップ（新規登録）機能仕様

## 概要

新規ユーザーが自身でアカウントとテナント（会社・工場）を作成し、アプリケーションの利用を開始できるサインアップ機能の仕様を定義します。

---

## ルート

| パス | 説明 |
|------|------|
| `/signup` | 新規登録画面 |

---

## 入力項目

| フィールド | 種別 | 必須 | バリデーション |
|-----------|------|------|---------------|
| 会社名 | テキスト | ✓ | 空白不可 |
| メールアドレス | email | ✓ | 空白不可・メール形式 |
| パスワード | password | ✓ | 8文字以上 |

---

## バリデーション

### クライアント側（送信前）

送信ボタン押下時に以下の順序でチェックを行い、最初のエラーを Sonner トースト（`入力エラー`）で表示します。

1. メールアドレスが空 → `メールアドレスを入力してください`
2. パスワードが空 → `パスワードを入力してください`
3. パスワードが8文字未満 → `パスワードは8文字以上で入力してください`
4. 会社名が空 → `会社名を入力してください`

### サーバー側（Supabase Auth）

| エラー | 表示メッセージ |
|-------|--------------|
| 既存メールアドレス（`already registered`） | `このメールアドレスはすでに登録されています` |
| その他のエラー | Supabase から返却されたエラーメッセージをそのまま表示 |

---

## 登録フロー

```
ユーザー入力
    │
    ▼
クライアント側バリデーション
    │ エラーあり → Sonner エラートースト表示
    ▼
supabase.auth.signUp({
  email, password,
  options: { data: { tenant_name } }
})
    │
    ▼
Supabase Auth: auth.users にレコード作成
    │
    ▼
DB トリガー: handle_new_user() 発火
    ├─ tenants テーブルにレコード作成 (name = tenant_name)
    └─ organization_members テーブルに追加 (role = 'admin')
    │
    ▼
登録成功 → Sonner 成功トースト表示 → / へリダイレクト
```

## UI/UX

### ローディング状態

送信ボタン押下から完了（成功・失敗）まで：
- ボタンテキスト: `登録中...`
- ボタン無効化（`disabled`）: 二重送信防止

### トースト通知

| タイミング | 種別 | タイトル | 説明 |
|-----------|------|---------|------|
| バリデーションエラー | エラー | `入力エラー` | バリデーションエラーメッセージ |
| 登録成功 | 成功 | `登録完了` | `アカウントを作成しました。ダッシュボードへ移動します。` |
| 登録失敗 | エラー | `登録失敗` | エラーメッセージ |

### リダイレクト

- 登録成功後: `/`（ダッシュボード）へ自動リダイレクト

### ナビゲーション

- ログインページ（`/login`）へのリンクを画面下部に表示

## アクセス制御

| 状態 | 動作 |
|------|------|
| 未ログイン | `/signup` にアクセス可能 |
| ログイン済み | ミドルウェアによりリダイレクト（`/signup` は認証不要パスに含まれる） |

`frontend/src/utils/supabase/middleware.ts` にて `/signup` パスは認証チェックの対象外として設定済みです。

## バックエンド実装

### Supabase DB トリガー

**ファイル:** `supabase/migrations/20260318000000_create_signup_trigger.sql`

| 項目 | 内容 |
|------|------|
| 関数名 | `public.handle_new_user()` |
| トリガー名 | `on_auth_user_created` |
| 発火タイミング | `AFTER INSERT ON auth.users` |
| 実行モード | `FOR EACH ROW` |
| セキュリティ | `SECURITY DEFINER`, `search_path = ''` |

**処理内容:**
1. `NEW.raw_user_meta_data->>'tenant_name'` からテナント名を取得
2. テナント名が存在する場合、`public.tenants` にレコードを作成
3. `public.organization_members` に `role = 'admin'` でユーザーを登録
4. 2・3 は `BEGIN...EXCEPTION` ブロックで保護し、片方が失敗した場合は例外を送出

### 使用テーブル

| テーブル | 操作 | 備考 |
|---------|------|------|
| `auth.users` | INSERT（Supabase Auth が自動実行） | トリガーの発火元 |
| `public.tenants` | INSERT | `tenant_name` を `name` として登録 |
| `public.organization_members` | INSERT | `role = 'admin'` で登録 |
