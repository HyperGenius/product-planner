# 設備マスタ設計 — 実装都合とUXの乖離

## 現状の整理

### DB構造

```
equipments          (設備の実体: 旋盤A, 溶接機B, ...)
equipment_groups    (設備をまとめるグループ: 切断グループ, ...)
equipment_group_members  (中間テーブル: どの設備がどのグループに属するか)
process_routings    (工程定義: equipment_group_id を参照 ← ここがポイント)
```

工程ルーティングは「設備グループ」に紐づく。個々の設備に直接紐づくわけではない。

### なぜ設備グループが存在するか

複数の工程で利用できる「汎用設備」があるため。たとえば同じ旋盤が「粗加工」工程でも「仕上げ」工程でも使われる場合、設備を直接工程に紐づけると同じ設備を複数の工程に「所属」させる表現が難しくなる。

設備グループを間に挟むことで:

- 1台の設備を複数のグループに追加できる
- 工程は「どのグループか」だけ知ればよく、物理的な設備の台数・構成の変動を吸収できる

### ユーザーの関心ごと

ユーザーが工程ルーティングを設定するとき、知りたいのは:

> **この工程では、どんな設備を使うのか**

「設備グループ」という概念はユーザーには自然でない。製造現場では「旋盤工程」「溶接工程」のように工程と設備は一体で語られることが多く、グループという抽象層を意識させる必要はない。

## 現状のUI上の問題

| 画面 | 表示されているもの | ユーザーが見たいもの |
|---|---|---|
| マスタトップ | 「設備」と「設備グループ」の2カード | 設備の管理（1つにまとめたい） |
| 工程ルーティング設定 | 「設備グループ」セレクトボックス | 「使用設備」として選択したい |

`product-routings-dialog.tsx` 内のラベルが `設備グループ` になっており、実装用語がそのままUIに出てしまっている。

---

## 今後のUI改善方針（案）

### 短期: ラベルの言い換え（実装変更なし）

実装構造はそのままに、UIの表現だけを変える。

| 現在 | 改善案 |
|---|---|
| マスタ画面カード: 「設備グループ」 | 「汎用設備グループ」または「設備グループ（上級設定）」 |
| 工程ルーティングのラベル: `設備グループ` | `使用設備` |
| 設備グループ管理画面のタイトル: `設備グループマスタ` | `設備グループ設定`（上級者向けと位置づけ） |

### 中期: マスタ画面の統合表示

「設備」管理画面の中で、その設備が属するグループも確認・編集できるようにする。設備グループ専用の管理画面はパワーユーザー向けに残す（またはマスタトップから非表示にして設備画面内に統合）。

```
/master/equipments  →  設備一覧 + 各設備の「所属グループ」列
                         → グループへの追加・削除はここから操作可能
/master/equipment-groups  →  廃止 or 設備画面内タブへ移動
```

### 長期: 工程ルーティングの設備選択UX改善

工程ルーティング設定ダイアログで、現在は「設備グループ」をセレクトボックスで選ぶ。これを以下のように改善する。

- グループ名だけでなく、所属する設備名も補足表示する（例: `切断グループ（旋盤A, 旋盤B）`）
- 単一設備しか持たないグループは、グループ名ではなく設備名で表示する

---

## 実装上の制約（変えるべきでないこと）

- `process_routings.equipment_group_id` の参照構造はスケジューリングアルゴリズム（`scheduler_logic.py`）が依存しているため、DB構造の変更は慎重に検討する
- 汎用設備（複数グループ所属）は実際に存在するユースケースであり、グループ概念自体を廃止することは適切でない
- 変えるべきは「ユーザーへの見せ方」であり「データモデル」ではない
